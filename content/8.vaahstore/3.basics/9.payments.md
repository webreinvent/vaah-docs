## Overview
In an e-commerce backend (VaahStore), the Payments CRUD is crucial for managing transactions, processing payments, and maintaining financial records. Here's an overview of its purpose, usage, and other details:

## Purpose
The Payments CRUD system handles the entire lifecycle of payment transactions within an e-commerce platform (journey of an order from cart to place order). Its primary functions include:

1. **Processing Transactions:**
    - Facilitates the processing of customer payments, ensuring that orders are paid for and completed

2. **Tracking Payment Status:**
    - Keeps track of the payment status for each transaction, including pending, success, or failure.
      ::alert{type="warning" class="p-4 mb-4 text-sm text-yellow-800 border border-yellow-300 rounded-lg bg-yellow-50 dark:bg-gray-800 dark:text-yellow-300 dark:border-yellow-800" role="alert"}
      NOTE
       - **Payment Status Impact:** Changes in payment statuses (e.g., success, failure, pending) affect the overall status of the **order**,
       - [Click here to read more](../8.vaahstore/basics/order-status-logics.md){:target="_blank"}.
3. **Managing Records:**
    - Maintain records of all payment transactions, which is essential for financial reporting and auditing also used in orders details page [order transaction history](../8.vaahstore/basics/11.orders.md#transaction-details-tab-panel){:target="_blank"}.

4. **Integration with Payment Gateways:** Payment gateways are integrated to support online payments. The system currently supports:
   - [PayPal](#paypal-flow)
   - [Stripe](#stripe-flow)
   - Cash on Delivery (COD)

## Usage:
- **Creating Payments:** Users can create new payment records, specifying details such as payment method, transaction ID, amount, and associated orders.
- **Viewing Payments:** Provides a comprehensive list of all payments with key details including payment ID, amount, date, status, and associated orders.
- **Updating Payments:** Allows modification of existing payment records to reflect changes or corrections, only updating payment notes .
- **Deleting Payments:** Enables the removal of payment records when necessary, adhering to business rules and compliance requirements.

## Handling Multiple Orders:
In VaahStore, a single payment can cover multiple orders. This functionality supports:
- **Multiple Orders per Payment:** Users can associate multiple orders with a single payment record. This is useful when a customer makes a single payment that covers several orders.
- **Order-Specific Amounts:** For each order included in a payment, the form displays
   - **Payable Amount:** The total amount that can be paid towards each order.
   - **Payment Amount:** The amount being paid for each specific order.
   - **Note:** For more detailed information on how to create payments, including step-by-step instructions and specific examples,
  please refer to the Create Payments as given below.

## Payment Gateway Integration

VaahStore integrates payment gateways directly in the **checkout flow** within the admin panel (backend Vue SPA). The checkout page is accessed at `/backend/store/carts/{id}` which renders the [CheckOut.vue](https://github.com/webreinvent/vaahstore/blob/master/Vue/pages/carts/components/CheckOut.vue) component. It provides three payment options:

1. **COD (Cash on Delivery)** — the "Place an order" button directly calls `Cart::placeOrder()` without any gateway.
2. **PayPal** — Renders the [PayPalButton.vue](https://github.com/webreinvent/vaahstore/blob/master/Vue/pages/carts/components/PayPalButton.vue) component.
3. **Stripe** — Renders the [StripeCheckout.vue](https://github.com/webreinvent/vaahstore/blob/master/Vue/pages/carts/components/StripeCheckout.vue) component.

All payment-related backend routes are defined in `VaahCms/Modules/Store/Routes/backend/routes-carts.php`.

### 1. PayPal Flow

PayPal integration uses the **PayPal Orders API v2** with the OAuth 2.0 client credentials flow.

---

**Step-by-step flow:**

1. **Frontend loads PayPal SDK** — [PayPalButton.vue](https://github.com/webreinvent/vaahstore/blob/master/Vue/pages/carts/components/PayPalButton.vue) dynamically loads the PayPal JS SDK script with the sandbox `client-id` from config.

2. **User clicks PayPal button** — The PayPal SDK calls the `createOrder` callback.

3. **Backend creates PayPal order** — The frontend sends a `POST /backend/store/carts/create-paypal-order` request with the `order_details`. [PayPalService::createOrder()](https://github.com/webreinvent/vaahstore/blob/master/Services/PayPalService.php):
   - Validates the cart via `Cart::validateOrderDetails()`
   - Obtains a PayPal OAuth 2.0 access token using client credentials
   - Builds the order payload with product items, pricing, and currency conversion
   - Sends `POST /v2/checkout/orders` to the PayPal REST API (sandbox)
   - Caches the order details for 30 minutes keyed by `paypal_order_{paypalOrderId}`
   - Returns the PayPal order ID to the frontend

4. **PayPal SDK resolves the order ID** — The PayPal approval UI (popup) is displayed to the user.

5. **User approves payment** — The user logs into PayPal and approves the payment in the popup.

6. **Backend captures PayPal order** — The PayPal SDK triggers `onApprove`, and the frontend sends a `GET /backend/store/carts/capture-paypal-order/{orderId}`. [PayPalService::captureOrder()](https://github.com/webreinvent/vaahstore/blob/master/Services/PayPalService.php):
   - Obtains a fresh OAuth token
   - Calls `POST /v2/checkout/orders/{id}/capture` on PayPal API
   - Verifies the payment status is `COMPLETED`
   - Reads the cached order details
   - Places the order in the database via `Cart::placeOrder()`
   - Records the payment via `Payment::createItem()` with `payment_method.slug = "paypal"` and the PayPal capture ID as `gateway_transaction_id`

7. **Redirect to confirmation** — The frontend navigates to the order confirmation page.

#### Backend Implementation Details

##### Key Endpoints (routes-carts.php)

```php
Route::post('/create-paypal-order', [PaymentsController::class, 'createOrder']);
Route::get('/capture-paypal-order/{id}', [PaymentsController::class, 'captureOrder']);
```

##### PayPalService::createOrder()
- **Validates** the cart data via `Cart::validateOrderDetails()`
- **Obtains** a PayPal OAuth access token using client credentials (client_id + client_secret from config `services.paypal`)
- **Builds** the order payload with:
  - Product items with name, unit_amount, and quantity
  - Currency conversion using the rate from the order's currency object
  - Intent: `CAPTURE` (immediate capture, not authorize)
- **Caches** the order details for 30 minutes keyed by `paypal_order_{paypalOrderId}`
- **Returns** the PayPal API response (contains the order ID)

##### PayPalService::captureOrder()
- **Fetches** cached order details
- **Captures** the PayPal order via `POST /v2/checkout/orders/{id}/capture`
- **Validates** payment status is `COMPLETED`
- **Places** the order in the database via `Cart::placeOrder()`
- **Records** the payment via `Payment::createItem()` with:
  - `payment_method.slug`: `paypal`
  - `gateway_transaction_id`: PayPal capture ID
  - `exchange_rate`, `payment_currency_code` from the order details
  - `notes`: "Paid via PayPal by {payer_email}"

### 2. Stripe Flow

Stripe integration uses **PaymentIntents API** with Stripe Elements on the frontend for PCI-compliant card data collection.

---

**Step-by-step flow:**

1. **Frontend fetches Stripe publishable key** — [StripeCheckout.vue](https://github.com/webreinvent/vaahstore/blob/master/Vue/pages/carts/components/StripeCheckout.vue) sends `GET /backend/store/carts/stripe/publishable-key`. The backend returns the Stripe publishable key from `config('services.stripe.key')`.

2. **Stripe Elements are mounted** — Stripe.js is loaded with the publishable key, a Stripe Elements instance is created, and a card input element is mounted in the DOM.

3. **User fills card details and clicks "Pay"** — The card number, expiry, and CVC are collected by Stripe Elements (PCI-compliant — card data never reaches the backend).

4. **Backend creates a PaymentIntent** — The frontend sends `POST /backend/store/carts/stripe/payment-intent` with the `order_details`. [StripeService::createPaymentIntent()](https://github.com/webreinvent/vaahstore/blob/master/Services/StripeService.php):
   - Validates the cart via `Cart::validateOrderDetails()`
   - Calculates the amount in the smallest currency unit (e.g., cents for USD). Zero-decimal currencies (like JPY) are handled separately.
   - Enforces a minimum of 50 in the smallest currency unit
   - Creates a Stripe PaymentIntent with `amount`, `currency`, `metadata.order_ref` (unique ref), and `automatic_payment_methods.enabled = true`
   - Caches order details for 30 minutes keyed by `stripe_payment_intent_{intentId}`
   - Returns only the `clientSecret` to the frontend

5. **Stripe.js confirms the payment** — The frontend calls `stripe.confirmCardPayment(clientSecret)` which sends the card details directly to Stripe (not to the backend).

6. **Backend confirms and places the order** — On successful card payment (status = `succeeded`), the frontend sends `POST /backend/store/carts/stripe/confirm-payment` with the `payment_intent_id`. [StripeService::confirmPayment()](https://github.com/webreinvent/vaahstore/blob/master/Services/StripeService.php):
   - Retrieves the PaymentIntent from Stripe to verify status is `succeeded`
   - Fetches the cached order details
   - Places the order in the database via `Cart::placeOrder()`
   - Records the payment via `Payment::createItem()` with `payment_method.slug = "stripe"` and the PaymentIntent ID as `gateway_transaction_id`
   - Clears the cache entry

7. **Redirect to confirmation** — The frontend navigates to the order confirmation page.

#### Backend Implementation Details

##### Key Endpoints (routes-carts.php)

```php
Route::get('/stripe/publishable-key', [PaymentsController::class, 'getStripeKey']);
Route::post('/stripe/payment-intent', [PaymentsController::class, 'createPaymentIntent']);
Route::post('/stripe/confirm-payment', [PaymentsController::class, 'confirmPayment']);
```

##### StripeService::createPaymentIntent()
- **Validates** cart data via `Cart::validateOrderDetails()`
- **Calculates** the amount in the smallest currency unit (e.g., cents for USD). Handles zero-decimal currencies like JPY specially.
- **Enforces** a minimum of 50 in the smallest currency unit
- **Creates** a Stripe PaymentIntent with:
  - `amount`, `currency` from order details
  - `metadata.order_ref`: unique reference (uniqid prefixed with `vh_`)
  - `automatic_payment_methods.enabled`: true
- **Caches** order details for 30 minutes keyed by `stripe_payment_intent_{intentId}`
- **Returns** only the `clientSecret` to the frontend (never expose the full PaymentIntent)

##### StripeService::confirmPayment()
- **Retrieves** the PaymentIntent from Stripe using the ID
- **Validates** status is `succeeded`
- **Fetches** cached order details
- **Places** the order via `Cart::placeOrder()`
- **Records** payment via `Payment::createItem()` with:
  - `payment_method.slug`: `stripe`
  - `gateway_transaction_id`: Stripe PaymentIntent ID
  - Amount converted from minor units (cents) back to main currency, then to store currency using the exchange rate
  - `notes`: "Paid via Stripe (PaymentIntent)"
- **Clears** the cache entry after successful processing

### 3. Currency Handling

Both payment gateways handle multi-currency through a currency object in the order details:

```php
$order['currency'] = [
    'code' => 'USD',         // ISO currency code
    'rate' => 1,             // Conversion rate relative to store default currency
    'symbol' => '$',
    'name' => 'US Dollar'
];
```

- **Conversion to Gateway Currency:** The payable amount is divided by the `rate` before sending to PayPal/Stripe
- **Conversion to Store Currency:** On recording the payment, the gateway amount is multiplied by the `rate` to store in the system's base currency
- **PayPal:** Converts using the merchant's configured currency (`services.paypal.currency`, default USD)
- **Stripe:** Sends the order currency directly, using Stripe's own conversion if needed

### 4. Payment Record Creation

The [Payment.php](https://github.com/webreinvent/vaahstore/blob/master/Models/Payment.php) model's `createItem()` method handles recording payments:

**Key steps:**

1. **Validation:** Validates the input (orders array, payment method, amounts)
2. **Transaction ID:** Generates a UUID v7 as the internal transaction reference
3. **Payment Gateway Fields:**
   - `payment_gateway`: Stores the slug (e.g., "paypal", "stripe")
   - `gateway_transaction_id`: The gateway's transaction identifier (PayPal capture ID, Stripe PaymentIntent ID)
   - `exchange_rate`, `payment_currency_code`: Currency conversion details
4. **Order Association:** Iterates through the orders array and:
   - Updates the `paid` amount on each order
   - Calculates the order payment status (`paid` or `partially-paid`)
   - Creates the pivot record in `vh_st_order_payments` table
   - Updates the order shipment status based on payment status
5. **Overall Payment Status:** Calculated as `success` if all orders were successfully processed, otherwise `pending`

## View Payments
In VaahStore, you can view payments in two primary ways:

1. **View All Payments:**
  - Navigate to the payments list page where all payments are displayed in a datatable.
  - This page shows a comprehensive list of all payments made, including key details such as payment ID, amount, date, and status.
    <img src="/images/vaahstore/payments/table.png" alt="payments-table.png">
    - **<u>ID:</u>** The unique identifier for each payment entry.
    - **<u>Transaction Id:</u>** The identifier for the transaction associated with the payment.
    - **<u>Amount:</u>** The total amount paid.
    - **<u>Payment Method:</u>** The method used for the payment (e.g., cod,credit card, PayPal).
    - **<u>Orders Count:</u>** The number of orders included in the payment.
    - **<u>Payment Status:</u>** The current status of the payment (e.g., success, failure).
    - **<u>Created At:</u>** The date and time when the payment record was created.
    - **<u>Actions:</u>** This column includes icons for performing various actions on the payment record:
      - **Edit:** Allows you to modify only the payment notes.
      - **Trash:** Provides an option to delete or move the payment to the trash.
      - **View:** Enables you to view detailed information about the payment.

  - To view detailed information about a particular payment, go to the view section for that payment.

    <img src="/images/vaahstore/payments/view-payment-details.png" alt="payments-view-payment-details.png">
    On clicking the view icon under the Actions column, you are redirected to the Payment Details and Order Payment Details page.

  - The page consists of two tab panels: Payment Details and Order Payment Details.

## Delete
Meaning : `Delete` refers to the action of removing a payment from the system or marking it as inactive.
Deleting a Payment is useful when you no longer want use that `Payment` .

There are various options to `Delete/Trash` a `Payment`
##### Dropdown Menu:

- Select the desired Payment from the list.
- Click on the dropdown menu.
- Choose the Delete option.
- Receive the success message `action was successful`.


##### Bulk Menu:
- Click on the three dots on the list page.
- Select Delete All.
- Confirm the action in the popup.
- Receive the success message `action was successful`.

##### Action Column:
- Click on the trash icon in the Actions column.
- Receive the success message `action was successful`.


## Restore
The `Restore` option allows you to reactivate a previously deleted or trashed payment. This is useful if you need to
recover a payment that was mistakenly deleted or temporarily removed. To restore a payment, follow the same steps as for
deletion, but select `Restore` instead.
