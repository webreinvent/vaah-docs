## Example 1: Load Test with Token-Based Authentication (Login + Authenticated API)
**Concepts Used:**
- Setup function
- Token-based authentication
- Custom headers
- ramping-vus executor with stages

::code-group
    ```bash [loginAuthTest.js]
    import http from 'k6/http';
    import { check, sleep } from 'k6';

    export let options = {
        scenarios: {
            auth_api_test: {
                executor: 'ramping-vus',
                startVUs: 0,
                stages: [
                    { duration: '30s', target: 20 },
                    { duration: '1m', target: 20 },
                    { duration: '30s', target: 0 },
                ],
            },
        },
    };

    export default function () {
        const loginPayload = JSON.stringify({ username: 'test', password: 'test123' });
        const loginHeaders = { 'Content-Type': 'application/json' };

        const res = http.post('https://test-api.k6.io/auth/token/login/', loginPayload, { headers: loginHeaders });
        const token = res.json('access');

        const headers = {
            Authorization: `Bearer ${token}`,
        };

        const res = http.get('https://test-api.k6.io/my/crocodiles/', { headers });

        check(res, {
            'is 200': (r) => r.status === 200,
        });

        sleep(1);
    }
::

## Example 2: Multiple Performance Testing Scenario in a Single Test
**Concepts Used:**
- `Stages`: Each scenario uses its own set of stages to define how VUs ramp up or down over time. Load Test, Spike Test and Soak Test:
- `Executor: ramping-vus`: Simulates a realistic load pattern by gradually increasing or decreasing the number of virtual users (VUs).
- `Custom cookies`: Custom cookies can be set per request (e.g., "new-website": "true").

::code-group
    ```bash [multipleScenarios.js]
    import http from 'k6/http';
    import { check, sleep } from 'k6';

    export let options = {
        scenarios: {
            load_test: {                                      // Load testing scenario
                executor: 'ramping-vus',
                stages: [
                    { duration: '30s', target: 100 }, // ramp up to 100 VUs in 30 seconds
                    { duration: '5m', target: 100 },  // stay at 100 VUs for 5 minutes
                    { duration: '30s', target: 0 },   // ramp down to 0 VUs in 30 seconds
                ],
            },
            spike_test: {                                     // Spike testing scenario
                executor: 'ramping-vus',
                stages: [
                    { duration: '30s', target: 200 }, // spike up to 200 VUs in 30 seconds
                    { duration: '1m', target: 200 },  // sustain 200 VUs for 1 minute
                    { duration: '30s', target: 0 },   // drop back to 0 VUs over 30 seconds.
                ],
            },
            soak_test: {                                      // Soak testing scenario
                executor: 'ramping-vus',
                stages: [
                    { duration: '5m', target: 50 },  // 50 VUs running continuously
                ]
            }
        },
    };

    export default function () {
        const urls = 'https://test-api.k6.io/';
    
        const res = http.get(url, {
            cookies: {
                "new-website": 'true',
            },
        });

        // Log the response time
        console.log(`${page} status: ${res.status}`);
        console.log(`${page} duration: ${res.timings.duration} ms`);

        // Perform the checks
        check(res, {
            [`${page} should return a 200-299 status code`]: (r) => r.status >= 200 && r.status < 300,
            [`${page} response time should be less than 7000s`]: (r) => r.timings.duration < 7000,
        });
    }

## Example 3: Testing E-commerce Checkout Flow
**Scenario**: Simulate a user browsing, adding an item to the cart, and checking out.
**Concepts:**
- User journey simulation
- Session/cookie management
- Chained HTTP requests

::code-group
    ```bash [checkoutFlow.js]
    import http from 'k6/http';
    import { check, sleep } from 'k6';

    export let options = {
        scenarios: {
            auth_api_test: {
                executor: 'ramping-vus',
                startVUs: 0,
                stages: [
                    { duration: '30s', target: 20 },
                    { duration: '1m', target: 20 },
                    { duration: '30s', target: 0 },
                ],
            },
        },
    };

    export default function () {
        let res1 = http.get('https://store.example.com/');
        check(res1, { 'home page loaded': (r) => r.status === 200 });

        let res2 = http.get('https://store.example.com/product/123');
        check(res2, { 'product page loaded': (r) => r.status === 200 });

        let res3 = http.post('https://store.example.com/cart', JSON.stringify({ productId: 123, quantity: 1 }), {
            headers: { 'Content-Type': 'application/json' },
        });
        check(res3, { 'item added to cart': (r) => r.status === 200 });

        sleep(1);

        let res4 = http.post('https://store.example.com/checkout', JSON.stringify({
            userId: 'user123',
            paymentMethod: 'credit_card',
        }), { headers: { 'Content-Type': 'application/json' } });

        check(res4, { 'checkout completed': (r) => r.status === 200 });
    }
::

## Example 4: Using Thresholds and Tags for Alerting
**Scenario**: Fail the test if 95% of requests take longer than 300ms.
**Concepts**:
- `thresholds`
- `tags` (to categorize metrics for filtering)
- `check()` assertions

::code-group
    ```bash [threshold.js]
    import http from 'k6/http';
    import { check } from 'k6';

    export let options = {
        thresholds: {
            'http_req_duration{type:homepage}': ['p(95)<300'], // 95% of homepage requests must be < 300ms
        },
    };

    export default function () {
        let res = http.get('https://example.com/', { tags: { type: 'homepage' } });

        check(res, {
            'status is 200': (r) => r.status === 200,
        });
    }
::
